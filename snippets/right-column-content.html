Designing RESTful APIs for Relational Data

This demonstration uses a RESTful API layer to expose structured data from a relational database (PostgreSQL). Each endpoint represents a resource and follows predictable, versioned patterns that support scalable application design. The API separates concerns by handling data access, transformation, and response formatting independently of the frontend. Key elements demonstrated:
  • Resource-based endpoints (/api/v1/courses, /api/v1/courses/:id/lessons)
  • Versioned API structure for maintainability and evolution
  • Clear mapping between relational models and API responses
  • Consistent JSON response format for frontend consumption

Interacting with Relational Databases (PostgreSQL)

The backend service interacts with a normalized relational schema, where courses and lessons are linked through foreign key relationships. The API retrieves and composes this data into structured responses without exposing underlying database complexity. This demonstrates how relational integrity and query design support clean API behavior. Key elements demonstrated:
  • One-to-many relationships (courses → lessons)
  • Use of foreign keys to maintain data integrity
  • Querying relational data and shaping it for API responses
  • Separation between database schema and external API contract

End-to-End Data Flow: API to Browser

This page demonstrates a full-stack interaction model, where the frontend dynamically retrieves data from a backend API and renders it in real time without page reloads. The system architecture separates presentation, API logic, and data storage into distinct layers, allowing each to evolve independently. Key elements demonstrated:
  • Asynchronous data retrieval using JavaScript (fetch API)
  • On-demand loading of related resources
  • Reverse proxy routing from Apache to Node.js backend
  • Clear separation between frontend, API, and database layers
